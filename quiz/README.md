# Token Wars - Takeaway Arena

A standalone, English-language workshop quiz with the leaderboard's neon style.
Project the dashboard, let participants scan its QR code, then close responses and
reveal the correct answers and reinforcement messages together.

## Event flow

1. Open `/` on the big screen. The dashboard refreshes every five seconds.
2. Each participant scans the QR code, chooses their team and answers up to **five**
   multiple-choice questions on `/join`. No personal name or sign-in is required.
3. A response is final. The server scores it; the phone never supplies its own score.
4. Teams are ranked by **accuracy = correct answers / all answers submitted by the
   team**. The board also shows correct/total answers and participant counts.
   Equal accuracy shares a rank; teams without responses are unranked. Larger teams
   do not get a ranking advantage merely by submitting more responses.
5. Use **Close responses**, then **Reveal answers**, entering the coach key for
   each action. Revealing is irreversible within an event. Correct answers,
   per-question results and takeaway messages appear on the board and phones.
6. **Download results** before **Reset event**. Reset requires the coach key and
   typing `RESET`; it permanently clears responses, creates a new event ID and
   allows everyone to participate again.

The default five questions cover targeted context, prompt caching, model
comparison, routing/escalation and the full-workload quality gate. This quiz has
its own scores; it neither changes nor connects to the cost-optimization leaderboard.

## Customize before the event

- Edit [questions.json](questions.json): **1-5 questions**, each with a unique
  `id`, `challenge`, `prompt`, 2-6 distinct `options`, a zero-based `correct_option`
  and a `takeaway` reinforcement message.
- Replace the sample team names in [teams.json](teams.json) with the event's
  teams. Participants select from this list to avoid spelling variants.
- Configuration is validated on startup; run the quiz locally once after editing
  to catch mistakes before deploying. Questions and teams are loaded at startup.
  To change them after responses exist, **download results and reset** first, then
  edit and redeploy. A changed configuration with existing responses fails
  explicitly instead of mixing scores.
- Do not redeploy or update the app during an active event: with the default
  container file system, a new revision starts with empty responses.

## Run locally

Requires Python 3.12+ and nothing else: like the leaderboard, the quiz uses only
the Python standard library (the QR code is generated by the bundled
[qr.py](qr.py)).

Bash (Linux, macOS, WSL or Git Bash):

```bash
cd quiz
read -rsp "Coach key: " QUIZ_ADMIN_KEY; echo; export QUIZ_ADMIN_KEY
python3 server.py
# Open http://localhost:8080
```

PowerShell:

```powershell
cd .\quiz
$env:QUIZ_ADMIN_KEY = [Net.NetworkCredential]::new("", (Read-Host "Coach key" -AsSecureString)).Password
python .\server.py
# Open http://localhost:8080
```

For an actual phone on the same Wi-Fi, set `PUBLIC_URL` to your computer's LAN
origin before starting, e.g. `export PUBLIC_URL="http://192.168.1.50:8080"` (Bash)
or `$env:PUBLIC_URL = "http://192.168.1.50:8080"` (PowerShell).
Open that same origin on the coach's browser. Allow the port through your firewall
only on a trusted network. `localhost` on a phone refers to the phone, not the
coach's computer. Use the Azure HTTPS deployment for a real event.

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `8080` | HTTP listen port |
| `DATA_DIR` | `quiz/data` next to the server | Persistent event state (`quiz.json`) and coordination lock |
| `PUBLIC_URL` | `http://localhost:<PORT>` | Exact public origin, used by the QR code and origin checks; no trailing path |
| `QUIZ_ADMIN_KEY` | empty | Coach-only secret; without it coach actions are disabled |

## Deploy to Azure Container Apps (one command)

From this folder (requires Azure CLI with the `containerapp` extension and
`az login`; the image is built in the cloud from the Dockerfile, so local Docker is
not required):

```bash
az containerapp up --name tokenwars-quiz --resource-group rg-tokenwars-quiz --location spaincentral --source . --ingress external --target-port 8080
```

After deployment, set the public URL used by the QR code, enable the coach
controls with a Container Apps secret, and keep exactly one replica so responses
are not split between instances:

```bash
FQDN=$(az containerapp show --name tokenwars-quiz --resource-group rg-tokenwars-quiz --query properties.configuration.ingress.fqdn -o tsv | tr -d '\r')
az containerapp secret set --name tokenwars-quiz --resource-group rg-tokenwars-quiz --secrets quiz-admin-key=<coach-only-key>
az containerapp update --name tokenwars-quiz --resource-group rg-tokenwars-quiz --min-replicas 1 --max-replicas 1 --set-env-vars PUBLIC_URL=https://$FQDN QUIZ_ADMIN_KEY=secretref:quiz-admin-key
echo "Dashboard: https://$FQDN   Participants: https://$FQDN/join"
```

PowerShell:

```powershell
$fqdn = az containerapp show --name tokenwars-quiz --resource-group rg-tokenwars-quiz --query properties.configuration.ingress.fqdn -o tsv
az containerapp secret set --name tokenwars-quiz --resource-group rg-tokenwars-quiz --secrets quiz-admin-key=<coach-only-key>
az containerapp update --name tokenwars-quiz --resource-group rg-tokenwars-quiz --min-replicas 1 --max-replicas 1 --set-env-vars "PUBLIC_URL=https://$fqdn" QUIZ_ADMIN_KEY=secretref:quiz-admin-key
"Dashboard: https://$fqdn   Participants: https://$fqdn/join"
```

Project the dashboard URL (`https://tokenwars-quiz.<env>.<region>.azurecontainerapps.io`);
its QR code points participants to `/join`. If the QR code shows `localhost`, the
`PUBLIC_URL` update step has not been applied yet.

Notes

- Use a coach-only key of at least 8 characters without spaces, and keep it in
  your password manager. Without `QUIZ_ADMIN_KEY`, the coach buttons are disabled.
- Data lives in the container file system. It survives page refreshes but **not**
  a new revision (redeploy or `az containerapp update`) or a container restart.
  Run the commands above before the event, then leave the app alone until results
  are downloaded. For a permanent quiz, mount an
  [Azure Files volume](https://learn.microsoft.com/azure/container-apps/storage-mounts)
  at `/app/data`.
- To change questions or teams later, rerun `az containerapp up` with the same
  command, then rerun the `PUBLIC_URL`/secret/replica commands.
- Download results with **Download results**, or `GET /api/admin/export` with
  `x-admin-key`.
- Clean up: `az containerapp delete --name tokenwars-quiz --resource-group rg-tokenwars-quiz`
  (or delete the resource group if it contains only the quiz).
## Fairness and privacy

- A random browser-local participant ID makes retries idempotent and prevents a
  refresh from adding another vote. Keep using the same browser for the event.
- This is an informal learning activity, **not an identity-verified competition**:
  another browser, incognito session or cleared site storage can submit again.
  No login means the server cannot enforce one response per physical person.
- Before reveal, public APIs contain no answer key, takeaway text or individual
  scores. The aggregate team leaderboard is public as requested.
- The coach key is entered per action, sent over HTTPS and never stored by the
  page. Exports include the answer key and all browser IDs/answers: keep them private.
- Responses are stored until the coach resets the event or the container's
  storage is replaced (see the deployment notes).
  No third-party QR service, CDN, analytics or AI model receives participant data.

## API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/state` | Questions, phase, join URL and team ranking; answers only after reveal |
| GET | `/api/state?participant_id=<uuid>` | Also include that browser's receipt; personal score/answers only after reveal |
| POST | `/api/responses` | `{event_id, participant_id, team, answers: {question_id: option_index}}`; `201` new, `200` identical retry, `409` stale/closed/duplicate change |
| POST | `/api/admin/close` | Close the current event |
| POST | `/api/admin/reveal` | Reveal a previously closed event |
| POST | `/api/admin/reset` | Clear responses and open a new event |
| GET | `/api/admin/export` | Download event, configuration, scores and all responses |
| GET | `/qr.svg` | Locally generated QR code for `PUBLIC_URL/join` |
| GET | `/healthz` | Checks persistent state can be read |

Coach endpoints require `x-admin-key`. Coach POST bodies require `{event_id}` to
guard against actions from a stale dashboard. Errors use `{error: "..."}` with
appropriate `4xx`/`5xx` status codes; storage failures never claim success.

## Tests

Run the dependency-free tests from the repository root:

```bash
python -m unittest discover -s quiz -p "test_*.py"
```

If the optional `qrcode` package is installed, `test_qr.py` also compares the
bundled encoder bit-for-bit with that reference library; otherwise those checks
are skipped.
